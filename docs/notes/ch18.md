# 18장 서비스 메시: Istio (쪽수 확인 필요)

## 명령
- Compose: `HOST=localhost PORT=8443 HEALTH_URL=https://localhost:8443 USE_K8S=false ./test-em-all.bash start stop` (교재 18장 기본값이 K8s로 바뀜)
- Istio: `istioctl install -f kubernetes/istio-tracing.yml -y`, Jaeger 애드온, `kubectl apply -f istio-telemetry.yml -n istio-system`
- `hands-on` 네임스페이스는 `hands-on-namespace.yml`(istio-injection 라벨) 먼저, `istio-system` 차트, `dev-env -f secrets.local.yaml`

## [Boot4] 변경
- 추적을 OTel에서 Brave(B3)로 전환: `micrometer-tracing-bridge-brave`, `zipkin-reporter-brave` + Boot 4 모듈 `spring-boot-micrometer-tracing-brave`, `spring-boot-zipkin`
- Zipkin 주소는 14장의 새 프로퍼티 `management.tracing.export.zipkin.endpoint` 유지(`jaeger-collector.istio-system:9411`)
- 인증 서버에서 `spring-retry`를 빼므로 17장에 되돌렸던 Cloud BOM도 교재대로 제거
- Mongo 환경변수 `SPRING_MONGODB_*`, helm `config-repo` 복사본(8곳, green 포함) 동기화, 비밀값 `secrets.local.yaml` 분리(렌더링 동일)

## 복습 포인트
- 사이드카 주입(파드 2/2)과 Istio Gateway/VirtualService가 Ingress를 대체. 서비스 간은 DestinationRule `ISTIO_MUTUAL`(mTLS)
- 라우팅용 `X-group` 헤더를 composite가 하위 서비스로 전달. blue/green은 prod-env의 VirtualService(`new`/`old` 서브셋, 렌더링만 확인)
- 액추에이터는 관리 포트 4004로 분리(프로브·헬스 URL 변경)
- 결과: build·Compose test-em-all 통과. K8s(Istio) test-em-all은 2회 모두 도중에 멈춰 미완료(1차 46개, 2차 10개 통과 후 정체)
- 미해결: composite 안에서 WebClient 응답이 30여 초 늦게 완료. Envoy·서버 스팬은 0초, 정체 중 이벤트 루프 12개가 `io_uring_enter` 대기. 16장과 같은 현상, 원인 불명
