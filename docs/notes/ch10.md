# 10장 Spring Cloud Gateway (쪽수 확인 필요)

## 명령
- 빌드: `cd ~/MSA/Chapter10 && ./gradlew build` (Docker 필요)
- 방식: 9장 사본 + 교재 9->10 변경분 / 통합 검증: `./test-em-all.bash start stop`
- 이제 외부 진입점은 gateway(8080) 하나. Eureka 대시보드는 `http://localhost:8080/eureka/web`

## [Boot4] 변경
- gateway `build.gradle`: Boot 4.0.7 / Java 21 / Cloud `2025.1.2`, 테스트용 `junit-platform-launcher` 추가
- gateway `HealthCheckConfiguration`: `boot.actuate.health.*` -> `boot.health.contributor.*`
- gateway Dockerfile 이미지 `21-jre-noble`
- 교재의 라우팅 속성 `spring.cloud.gateway.server.webflux.*`는 Cloud 2025.1.x에서도 그대로 사용

## 복습 포인트
- composite의 외부 포트(8080) 제거 -> gateway가 8080을 받고 `lb://product-composite`로 전달
- 헬스체크 집계(`HealthCheckConfiguration`)가 composite에서 gateway로 이동
- `server.forward-headers-strategy: framework`: gateway가 붙인 X-Forwarded-* 로 Swagger URL 생성
- `eureka-api`/`eureka-web-*` 라우트의 `SetPath`로 `/eureka/api/apps` -> `/eureka/apps` 재작성
- Host 헤더 기반 `headerrouting` 라우트는 외부 `httpstat.us`에 의존 (서비스 종료 시 해당 테스트 실패 가능)
- 결과: 전체 build 통과, RabbitMQ `test-em-all.bash start stop` 통과 (첫 빌드에서 review 테스트가 5초 타임아웃으로 1건 실패, 재실행 시 통과 = 첫 MySQL 컨테이너 기동 지연)
