# 17장 Config Server·Gateway를 쿠버네티스 기능으로 대체 (쪽수 확인 필요)

## 명령
- 빌드 `cd ~/MSA/Chapter17 && ./gradlew build`, Compose `./test-em-all.bash start stop` (`.env.example`을 `.env`로 복사해 값 채움)
- 클러스터: minikube + `addons enable ingress`, cert-manager(`helm install ... --set crds.enabled=true`), 이미지 로드
- 설치: `helm install hands-on-dev-env environments/dev-env -f environments/dev-env/secrets.local.yaml -n hands-on`
- 검증(WSL): ingress 컨트롤러 포트 포워딩(8443:443) 후 `HOST=minikube.me PORT=8443 USE_K8S=true ./test-em-all.bash`

## [Boot4] 변경
- Mongo 환경변수 `SPRING_DATA_MONGODB_*` -> `SPRING_MONGODB_*` (compose 3개, helm values). yml이 `spring.mongodb.*`라서 같은 이름으로 맞춤
- 인증 서버: Cloud 의존성이 모두 빠져도 Cloud BOM 유지. Boot 4 BOM은 `spring-retry` 버전을 관리하지 않아 교재처럼 BOM을 지우면 해석 실패
- composite는 `spring-boot-starter-aspectj` 유지 (Resilience4j 어노테이션용. Config Client 의존성과 별개)
- helm 서비스별 `config-repo` 복사본을 17장 `config-repo`(Boot 4 설정)로 동기화 필수
- [저장소] 비밀값은 `secrets.local.yaml`(gitignore)로 분리, `secrets.example.yaml`·`.env.example` 커밋

## 복습 포인트
- Config Server 없이: `SPRING_CONFIG_LOCATION=file:/config-repo/...`(Compose 볼륨) / ConfigMap(K8s). 비밀번호는 환경변수(Secret)
- Gateway 대신 Ingress(`minikube.me`) + cert-manager 자체 서명 Issuer가 TLS 종단. `bootstrap.yml`은 사라지고 이름·로그 패턴은 config-repo로 이동
- WSL에서 `minikube.me` 해석은 `/etc/hosts` 대신 `CURL_HOME`의 임시 `.curlrc`(`resolve`)로 처리
- 결과: Compose·K8s(Ingress) test-em-all 통과. 16장의 간헐 지연은 이번엔 재현되지 않음
