# 14장 분산 추적: Micrometer Tracing + Zipkin (쪽수 확인 필요)

## 명령
- 빌드: `cd ~/MSA/Chapter14 && ./gradlew build` (Docker 필요) / 이미지 갱신: `docker compose build`
- 통합 검증: `./test-em-all.bash start stop`. 추적은 test-em-all에 없어 `localhost:9411`(Zipkin)에서 직접 확인

## [Boot4] 변경
- 추적 의존성: 교재의 `micrometer-tracing-bridge-otel` + `opentelemetry-exporter-zipkin`에 `spring-boot-micrometer-tracing-opentelemetry`, `spring-boot-zipkin` 추가 (Boot 4는 자동 구성이 모듈로 분리됨)
- Zipkin 주소: `management.zipkin.tracing.endpoint` -> `management.tracing.export.zipkin.endpoint` (config-repo/application.yml)
- `ObservationRegistryCustomizer` import: `boot.actuate.autoconfigure.observation` -> `boot.micrometer.observation.autoconfigure`
- review: `datasource-micrometer-spring-boot` 1.0.0 -> 2.3.1 (DB 쿼리 스팬)
- composite Application은 OpenAPI 빈 유지, `@LoadBalanced` 빌더를 `WebClient` 빈 + 로드밸런서 필터로 교체

## 복습 포인트
- 한 요청 = traceId 하나, 서비스/호출마다 spanId. 로그 패턴 `[서비스,traceId,spanId]`(bootstrap.yml)
- 샘플링 `probability: 1.0`(전부 수집, 개발용). zipkin-server는 메모리 저장(`STORAGE_TYPE=mem`)
- `Hooks.enableAutomaticContextPropagation()`: 리액티브 스레드 전환에서 추적 컨텍스트 전달
- `WebClient`를 Builder에서 만들어야 관찰(Observation)이 적용돼 다른 서비스로 헤더가 전파된다
- `ObservationUtil`로 `product info` 수동 스팬 + `productId` 태그, `BuildInfoObservationFilter`로 build.version 태그
- 결과: test-em-all 통과(서킷 브레이커 포함), Zipkin에 서비스 7개, 한 추적이 gateway~review까지 21스팬
