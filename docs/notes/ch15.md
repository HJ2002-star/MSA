# 15장 쿠버네티스 소개 (쪽수 확인 필요)

## 명령
- 빌드: `cd ~/MSA/Chapter15 && ./gradlew build`. 코드는 14장과 기능상 동일 (형식 정리만)
- 실습: `minikube start --profile=<이름> --driver=docker --cpus=2 --memory=4096`
- 적용: `kubectl apply -f kubernetes/first-attempts/` / 확인: `kubectl get deploy,pods,svc`
- 스케일: `kubectl scale deploy nginx-deploy --replicas=3`
- 접속(WSL): `kubectl port-forward svc/nginx-service 18080:80`, 정리: `minikube delete --profile=<이름>`

## [Boot4] 변경
- 없음. 14장의 Boot 4 수정이 그대로 이어진다 (교재 15장의 코드 변경은 테스트 로그 옵션 제거·접근 제어자 등 형식뿐)
- WSL + Docker Desktop에서는 minikube NodePort(`minikube ip`:30080)에 WSL에서 닿지 않는다. 노드 안에서는 200

## 복습 포인트
- Deployment = 원하는 상태(replicas, 이미지), ReplicaSet이 파드 수를 유지. 파드를 지우면 새 파드로 교체된다
- Service(NodePort)는 `selector`의 라벨(`app: nginx-app`)로 파드를 찾아 부하 분산
- `kubectl apply`는 선언형: 파일이 바뀐 만큼만 반영
- Docker Compose의 서비스 이름 DNS는 쿠버네티스에서 Service 이름 DNS로 이어진다 (16장 이후)
- 결과: build 통과, minikube(4GB)에서 배포·스케일 3·파드 삭제 복구·port-forward 200 확인 후 클러스터 삭제
