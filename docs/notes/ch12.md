# 12장 Spring Cloud Config Server (쪽수 확인 필요)

## 명령
- 빌드: `cd ~/MSA/Chapter12 && ./gradlew build` (Docker 필요) / 이미지 갱신: `docker compose build`
- 통합 검증: `./test-em-all.bash start stop` (compose가 `.env`의 CONFIG_SERVER_* 값을 읽는다)
- 방식: 11장 사본 + 교재 11->12 패치. 서비스 `application.yml`은 삭제되고 `config-repo/*.yml`로 이동

## [Boot4] 변경
- 이전 장의 Boot 4 yml 수정은 `config-repo`에 다시 넣어야 한다: `spring.mongodb`(product, recommendation), `spring.jackson.mapper.allow-final-fields-as-mutators`, `spring.web.error.include-message`
- 테스트는 Config Server를 끄므로(`spring.cloud.config.enabled=false`) 같은 설정을 `src/test/resources/application.yml`에도 둔다
- `spring-boot-starter-aop` -> `spring-boot-starter-aspectj` (Boot 4 스타터 이름). `starter-bootstrap`, `spring-retry`는 교재대로
- config-server `build.gradle`: Boot 4.0.7 / Java 21 / Cloud 2025.1.2, `junit-platform-launcher`. Dockerfile `21-jre-noble`

## 복습 포인트
- 설정 로딩 순서: `bootstrap.yml`(config server 위치·계정) -> config-repo `application.yml`(공통) + `서비스명.yml`
- 비밀값은 `{cipher}...`로 저장, config-server가 `ENCRYPT_KEY`로 복호화. `/encrypt`, `/decrypt` 엔드포인트
- config-server는 Basic 인증(`CONFIG_SERVER_USR/PWD`), gateway가 `/config/**`를 8443으로 노출
- failFast + retry: config-server가 늦게 떠도 서비스가 재시도한다
- 알려진 불안정: review 단위 테스트 `getReviewsMissingParameter`가 첫 요청 5초 타임아웃으로 간헐 실패 (11장에서도 재현, 12장 변경과 무관)
- 결과: config-server 포함 test-em-all 통과
