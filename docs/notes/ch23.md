# 23장 GraalVM 네이티브 이미지 (쪽수 확인 필요)

## 명령
- JVM 빌드 `cd ~/MSA/Chapter23 && ./gradlew build` (Docker 필요). 네이티브: `./gradlew :microservices:<서비스>:bootBuildImage` (서비스당 약 5~6분, 메모리 약 12GB 사용, 한 번에 하나씩)
- Compose 네이티브: `COMPOSE_FILE=docker-compose-native.yml HOST=localhost PORT=8443 HEALTH_URL=https://localhost:8443 USE_K8S=false ./test-em-all.bash start stop`
- K8s: `helm install ... environments/dev-env-native -f .../secrets.local.yaml` (이미지 `hands-on/native-*`는 minikube에 로드)

## [Boot4] 변경
- GraalVM 플러그인 `0.10.6` -> `0.11.5`(Boot 4.0.7 BOM 관리 버전)
- 빌드팩이 Boot 4 + NIK 25 미만을 거부 -> `bootBuildImage`에 `BP_JVM_VERSION=25` (컴파일 툴체인은 Java 21 유지)
- `@RegisterReflectionForBinding`의 `ZonedDateTimeSerializer`를 Jackson 3(`tools.jackson.databind.ext.javatime.ser`)로 교체
- composite에 `Health`·`Status`(`boot.health.contributor`) 힌트 추가. 없으면 서킷 브레이커 헬스의 중첩 `Health`가 `{}`로 직렬화됨
- helm Mongo 환경변수 `SPRING_MONGODB_*`, 비밀값 `secrets.local.yaml` 분리(렌더링 동일)

## 복습 포인트
- 같은 서비스가 네이티브는 기동 0.8~2.4초, JVM은 18~23초. composite 메모리 124MiB 대 301MiB. 네이티브 컨테이너엔 셸이 없어 test-em-all은 auth-server에서 wget
- 네이티브는 빌드 시점 AOT 분석이라 리플렉션·리소스 힌트가 필요하다(`NativeHintsConfiguration`, `@RegisterReflectionForBinding`)
- `jar` 비활성 해제로 `build/libs`에 jar가 2개지만 `ADD *.jar`는 정렬상 마지막(부트 jar)이 app.jar가 되어 우연히 동작
- 결과: JVM·네이티브 Compose test-em-all 통과(64개), K8s(Istio)에서 네이티브 파드 전부 Ready, 생성·조회·401·서킷 헬스 확인
- 미검증: 네이티브 단위 테스트(`nativeTest`), 파티션 compose, K8s test-em-all 전체. 클러스터 직후 istiod가 auth-server JWKS를 못 가져와 Envoy가 401(istiod 재시작으로 해소, 시작 순서 경합)
