# 20장 모니터링: Prometheus·Grafana (쪽수 확인 필요)

## 명령
- 빌드 `cd ~/MSA/Chapter20 && ./gradlew build` / Compose `HOST=localhost PORT=8443 HEALTH_URL=https://localhost:8443 USE_K8S=false ./test-em-all.bash start stop`
- 지표 확인(Compose): `docker compose exec product-composite wget -qO- http://localhost:4004/actuator/prometheus`
- K8s는 파드 어노테이션(`prometheus.io/scrape/port/path`)으로 Prometheus가 4004 포트를 수집. Grafana 대시보드 JSON은 `kubernetes/grafana`

## [Boot4] 변경
- 없음. 교재의 `micrometer-registry-prometheus` 한 줄만으로 Boot 4에서 `/actuator/prometheus`가 노출됨(5개 서비스 모두 200)
- 코드 18~19장과 동일 + 의존성 5곳(composite, product, recommendation, review, auth-server), `management.metrics.tags.application`
- helm `config-repo` 복사본 동기화 필요(application.yml이 바뀜), 비밀값은 `secrets.local.yaml` 분리 유지

## 복습 포인트
- 모든 지표에 `application="서비스명"` 태그가 붙어 Grafana에서 서비스별로 필터링한다
- JVM·HTTP 서버/클라이언트 지표와 Resilience4j 서킷 상태(`resilience4j_circuitbreaker_state`)가 함께 나온다
- prod 프로파일은 노출 엔드포인트를 `health,info,circuitbreakerevents,prometheus`로 제한
- gateway(Spring Cloud Gateway)에는 레지스트리를 추가하지 않는다(교재 그대로). Istio 인그레스가 대신 지표를 낸다
- 결과: 빌드·Compose test-em-all 통과, 서비스 5개 지표 확인, 차트 lint·렌더링(어노테이션 5곳) 통과
- 미검증: Prometheus·Grafana 애드온, 메일 서버(알림), K8s test-em-all의 `health.minikube.me/actuator/prometheus` 항목은 실행하지 않음
