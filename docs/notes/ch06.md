# 6장 데이터베이스 영속성 (쪽수 확인 필요)

## 명령
- 전체 테스트: `cd ~/MSA/Chapter06 && ./gradlew test` (Docker 필요, 첫 실행은 이미지 pull)
- 통합 검증: `./gradlew build` 후 `./test-em-all.bash start stop`
- 시작 전 `docker compose down`으로 이전 장 컨테이너를 내린다 (8080 충돌)

## [Boot4] 변경
- MongoDB 키: `spring.data.mongodb.host/port/database` -> `spring.mongodb.*` (yml 3곳 + Application 로그). 옛 키는 error 수준 제거라 값이 무시된다.
- Testcontainers 2.x: artifact가 `testcontainers-junit-jupiter`, `-mongodb`, `-mysql`로 바뀜
- 테스트 스타터 추가: `starter-data-mongodb-test`, `starter-data-jpa-test`
- `@DataMongoTest`, `@DataJpaTest` 패키지 이동 (`org.springframework.boot.data.*.test.autoconfigure`)
- 테스트 헬퍼의 `isEqualTo(expectedStatus)` -> `.value()` (422 enum 불일치)
- composite: 5장의 Jackson 3, `UNPROCESSABLE_CONTENT` 수정을 6장 코드에 다시 적용

## 복습 포인트
- 엔티티의 `@Version`(낙관적 락)과 `@Indexed(unique)`가 중복 키/동시 수정을 어떻게 막는지
- MapStruct 매퍼가 API 모델과 엔티티를 변환하는 방식 (`rate` <-> `rating` 매핑)
- 생성은 중복 시 422, 삭제는 멱등(없어도 200)
- `@ServiceConnection`으로 Testcontainers 접속 정보를 자동 연결
- 결과: 테스트 54개 통과, `test-em-all` 통과
