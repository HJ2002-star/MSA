# 16장 쿠버네티스 배포: Helm, Eureka 제거 (쪽수 확인 필요)

## 명령
- 빌드 `./gradlew build`, Compose `./test-em-all.bash start stop` / 클러스터: `minikube start -p handson-spring-boot-cloud --cpus=4 --memory=8192`
- 이미지 로드, `helm dependency update`(components→environments), 설치: `helm install hands-on-dev-env environments/dev-env -f environments/dev-env/secrets.local.yaml -n hands-on --create-namespace`
- K8s 검증: `kubectl -n hands-on port-forward svc/gateway 30443:443` 후 `HOST=localhost PORT=30443 USE_K8S=true ./test-em-all.bash`

## [Boot4] 변경
- 코드는 Eureka 제거 + `config-repo` 수정. 이전 장 Boot 4 설정(`spring.mongodb`, Jackson, `include-message`, zipkin 새 프로퍼티)을 `config-repo`에 유지하고 교재 변경만 반영
- `components/config-server/config-repo`는 원본의 복사본이라 `config-repo` 수정 후 동기화해야 한다 (안 하면 클러스터는 옛 설정을 쓴다)
- readiness 그룹의 `mongo`/`db`/`rabbit` 이름은 Boot 4에서도 유효 (compose에서 `/actuator/health/readiness`로 확인)
- [저장소] 샘플 비밀값은 `values.yaml`에서 `secrets.local.yaml`(gitignore)로 분리, `secrets.example.yaml`을 복사해 채운다. 렌더링 결과는 분리 전과 동일
- WSL: NodePort 직접 접속 불가라 `kubectl port-forward` 사용

## 복습 포인트
- Eureka/`lb://` -> 쿠버네티스 Service 이름 DNS(`http://product-composite`). docker 프로파일 포트 80
- Helm: `common` 라이브러리 차트 + 컴포넌트 차트 + `dev-env`/`prod-env` 환경 차트. 이미지 `pullPolicy: Never`라 미리 로드
- liveness/readiness 프로브, graceful shutdown, `ResilienceConfig`(`app.resilience.enabled`로 Resilience4j 끄기)
- 결과: Compose·dev-env(K8s) test-em-all 통과. prod-env는 lint·렌더링만
- 미해결: K8s 실행 중 composite->recommendation/review 호출이 간헐적으로 42~88초 지연되는 현상을 2회 겪음(파드 재시작 후 사라지고 3번째 전체 실행 통과). 원인 불명
